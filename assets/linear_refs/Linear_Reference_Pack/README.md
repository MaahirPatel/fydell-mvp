## What Linear is actually doing well

### 1. One visual language across every page

Linear's homepage, Intake page, Pricing page, and Security page use the same:

- 72px desktop navigation;
- Inter Variable / SF Pro Display typographic stack;
- near-black `#08090a` canvas;
- subtle neutral borders;
- restrained radii;
- disciplined left and right page gutters;
- heading weight around 500–510 rather than heavy bold;
- quiet secondary text;
- product-led imagery;
- section numbering and repeated product nomenclature;
- footer and final CTA language.

The pages do not look identical, but they clearly belong to one system.

### 2. Typography carries the page

Measured at a 1363px-wide desktop viewport:

- Homepage navigation: 72px tall.
- Homepage H1: 64px size, 64px line height, weight 510.
- Homepage major H2: 48px size, 48px line height, weight 510.
- Product-page H1: up to 72px with 72px line height.
- Security H1: 64px, approximately 68px line height.
- Body: 16px/24px Inter Variable.

These numbers are observations, not a command to copy every value. For Fydell, the relevant lesson is a small, intentional type scale used consistently. Avoid mixing a 68px homepage with 46px secondary heroes, 26px auth headings, and unrelated gradient headings unless the differences come from a documented scale.

### 3. Product is the imagery

Linear's first major visual is a large product state spanning nearly the full viewport width. Later sections continue with product scenes that explain distinct workflow moments. The visuals use real product nouns, legible interface states, accurate UI relationships, and carefully controlled crops.

Fydell's equivalent is not a random office, ocean, building, face, or abstract 3D object. It is:

- the Northline Data Analyst workbench;
- source files and a selected data range;
- a calculation becoming a claim;
- a claim opening onto the exact supporting rows;
- a metric-definition change challenging the first conclusion;
- the candidate revision delta;
- an oral-defense question tied to that limitation;
- the employer evidence report;
- the candidate-controlled Work Receipt;
- the outcome-calibration loop.

### 4. Visual richness comes from structure

Linear uses:

- large product canvases;
- layered but aligned interface states;
- borders and grids;
- semantic connection lines;
- restrained gradients and glows;
- high-quality crops;
- consistent chapter spacing;
- controlled contrast;
- clear product labels.

It does not become rich by placing unrelated stock photographs inside headlines or feature cards.

### 5. Motion supports meaning

Linear does contain motion, but the page remains understandable when still. Motion reveals, transitions, or advances product state. It is not the core layout mechanism.

For Fydell:

- allow short opacity/translate reveals only when they improve orientation;
- allow a citation highlight, claim selection, or revision change to animate briefly;
- allow a product-scene tab to change after a deliberate click;
- disable all nonessential movement under `prefers-reduced-motion`;
- never require scrolling to unscramble overlapping cards;
- never use auto-running marquees, scroll-pinned chapter piles, parallax, hover tilt, floating cards, fake cursor paths, or continuous decorative loops.
